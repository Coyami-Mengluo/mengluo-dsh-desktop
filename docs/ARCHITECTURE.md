# 架构速览 / Architecture overview

本文面向维护者和贡献者，说明当前实现的边界；不是对未来官方版本的兼容性保证。桌面产品目前仅支持 Windows x64。Linux/macOS 的源码测试不代表提供对应安装包。

## 1. 外壳与官方界面

[main.mjs](../src/main.mjs) 是生命周期入口，创建主窗口、托盘、设置和两种更新管理器，并监督独立 Node 子进程。窗口关闭按钮默认隐藏到托盘；菜单“退出”才执行后台清理。

[desktop-window.mjs](../src/desktop-window.mjs) 在同一窗口中组合两个不同的渲染进程：本地标题栏与官方 `WebContentsView`。标题栏、设置、首次安装和进度界面由 `assets/` 提供；官方页面直接来自本机 Harness 服务，不复制或改写官方前端。官方页面没有本项目的 preload，也没有客户端设置 IPC 权限。

后台使用槽位内的独立 Node 启动官方 CLI；[backend-runner.mjs](../src/backend-runner.mjs) 仅作生命周期预加载，保留 CLI 的真实入口语义。请求端口只是首选值；实际导航地址取自受监督子进程输出的有效 `127.0.0.1` 就绪 URL，保留鉴权参数。普通外部链接交给系统浏览器，Harness 自身 UI 保持在壳内。

顶栏通过官方页面顶部窄条的像素采样匹配背景和渐变，不向官方页面注入脚本。客户端语言独立保存，不翻译官方界面或社区内容。相关实现：[titlebar-sampler.mjs](../src/titlebar-sampler.mjs)、[language.mjs](../src/language.mjs)。

## 2. 运行时槽位与数据归属

[runtime-store.mjs](../src/runtime-store.mjs) 管理客户端用户资料目录下的 `harness-runtimes/<version>` 和 `harness-runtime-state.json`。每个槽位含自己的 Node、许可证、官方软件包和生产依赖。状态中的 `pendingVersion`、`activeVersion`、`previousVersion` 分别表示待切换、当前与可回退版本；失败版本另行记录。

- 安装包只带外壳及安装用 Node/npm，不预装 Harness。首次启动从官方获取版本列表，由用户确认安装。
- 新版本先在候选目录安装、校验和启动测试，再登记为待切换版本。启用后还需实际官方界面加载并稳定，才确认就绪；已有可用槽位不会在下载开始时被覆盖。
- 槽位关键文件与前端目录有完整性封印。它能发现本地意外修改，但不是抵御同账户恶意程序的安全沙箱或远程签名。
- 聊天、工作区和插件 profile 不属于可替换运行时槽位。插件实际目录由官方 home 规则解析，使用 `profiles/web`；客户端自身偏好、日志、插件来源记录和快照分别保存。切勿把这些用户资料纳入源码或安装包。

后台结束先走私有 IPC → 官方正常退出路径；超时才清理本壳记录的进程树。未确认旧后台退出，不再启动并行实例或交换插件文件。插件重启只重启当前后台，保留窗口和另行准备的更新；启动完成依赖实际界面就绪，不以“进程已创建”代替成功。

## 3. 两条互不替换的更新路径

[runtime-versions.mjs](../src/runtime-versions.mjs) 提供用户主动选择的历史版本安装与离线切换。设置 IPC 只接受固定动作和严格版本号；下载目标须存在于官方目录，已安装版本须经独立 worker 校验封印与隔离启动。手动安装只准备槽位，不登记待切换；确认切换后才写入 `pendingVersion` 并重启。切换自动设置 `versionLocked`，锁定期间自动检查仅提醒。与插件修改、普通 Harness 更新及客户端安装互斥。

降级先暂停后台，再通过 [plugin-snapshots.mjs](../src/plugin-snapshots.mjs) 的受限字节复制器备份整个 Harness home 及客户端插件来源记录。此备份与插件快照保留/回滚系统分离，不自动删除、恢复或上传；只有校验完整副本和源数据均未变化后，才写入完成清单。上限 2 GiB / 100000 项，外部链接和不安全路径拒绝。失败不会登记版本切换。启动失败的运行时回退不等同于恢复官方数据格式，具体风险见 README。

独立壳窗口共用 [window-placement.mjs](../src/window-placement.mjs)，在首次显示或从隐藏恢复时相对主窗口居中，并限制在主窗口所在显示器的工作区。可见窗口不重新定位，保留用户拖动位置。

| 路径 | 来源与校验 | 下载和启用 |
| --- | --- | --- |
| 官方 Harness | 官方 npm 的版本、精确依赖图、完整性信息；独立 Node 与官方配套依赖 | [update-manager.mjs](../src/update-manager.mjs) 可自动检查并准备候选；通过隔离测试后等待确认重启切换 |
| 桌面客户端 | 固定 GitHub 仓库 Release；安装器名称、大小、SHA-512 等校验 | [shell-updater.mjs](../src/shell-updater.mjs) 检查只提醒，下载和重启安装均需确认；支持缓存/blockmap 差分，条件不满足时全量下载 |

Harness 更新不是增量替换正在运行的目录；npm 准备、镜像下载和官方源重试共用 30 分钟预算，校验与启动测试另有边界。客户端差分更新减少传输量，但最终仍得到完整安装器，不是在线修改 `app.asar`。

npmmirror 只改变受管理 Harness 的 npm 包下载途径；版本、依赖和 SHA-512 仍以官方为准，缺包或网络故障可在预算内回退官方同版本文件。它不改变 GitHub 壳更新、Git 插件或系统全局 npm 配置。

连接检测在已有目标版本时读取官方与镜像的同版本 `@deepseek-ai/dsh` 元数据并对比完整性摘要；首次安装使用下拉框中选定的官方版本，设置页优先检测待切换/可更新版本，否则检测当前版本。元数据一致仅表示该条目已同步，不保证全部依赖和包文件可下载。检测不安装、不自动触发镜像同步，也不绕过后续校验。

## 4. 插件管线与恢复

[plugin-catalog.mjs](../src/plugin-catalog.mjs) 负责远程搜索和只读版本检查；[plugin-manager.mjs](../src/plugin-manager.mjs) 协调原生确认、互斥、快照与 CLI 操作；[plugin-runtime.mjs](../src/plugin-runtime.mjs) 绑定当前运行时及 `web` profile 执行受限参数。渲染进程只能传固定动作和插件 ID，不能指定命令、下载 URL 或目标路径。

安装/更新/卸载的顺序为：主进程解析候选 → 用户确认 → 重新确认版本与清单未变化 → 创建操作前完整快照 → 官方命令执行 → 核查结果并记录。npm 使用精确版本，GitHub 来源固定完整提交。只检测更新，不自动升级插件。完成后用户可点“重启 Harness”，再次确认中断任务后加载变更。

搜索、翻页、目录刷新共享主进程限额；本地冷却、GitHub 搜索额度、插件元数据额度与服务临时限流分别标示。保留缓存，不自动循环重试，也不通过切换来源规避真实限流。

[plugin-snapshots.mjs](../src/plugin-snapshots.mjs) 保存整个 `web` profile 和客户端插件来源记录，校验摘要、链接边界、当前内容与运行时版本后才能离线回滚。恢复先停止后台；中断事务会阻止启动，须显式修复。快照在本机未加密，不包含聊天/工作区，也不能撤销插件对目录外文件或外部服务造成的影响。快照不等于插件沙箱。

## 5. 信任边界与修改入口

- **本地界面 → 主进程：**隔离上下文、关闭 Node 集成；核验固定文件 URL、准确的 webContents 和 mainFrame；动作与字段白名单。新增按钮必须同时补主进程验证、忙碌/取消/失败测试，不能只在前端禁用。
- **网络 → 下载器：**只允许固定来源，限制响应、超时及重定向。社区名称/描述按纯文本展示；远端元数据是待验证输入，不能成为指令。鉴权 URL、令牌和本地路径不直接显示为错误详情。
- **官方与第三方代码 → 本机：**官方运行时和用户确认安装的插件是可执行代码，具有运行账户相应的文件和网络能力。社区收录不是安全审核；Electron 渲染隔离不能限制后端插件的权限。
- **发布账户 → 用户设备：**当前安装包未配置 Windows 发布者签名。HTTPS 与摘要能发现传输损坏，不能抵御被接管的 GitHub/npm 发布账户。维护者应保护账户、审查依赖和保留许可声明。

测试入口见 [CONTRIBUTING.md](../CONTRIBUTING.md)。真实 Electron、cmd、Windows junction 和安装器测试在 Windows 执行；便携逻辑在多平台检查。原生冒烟使用独立临时资料与合成/模拟数据，不应连接维护者的实际聊天目录。发布授权和人工产物检查仍按 [RELEASING.md](RELEASING.md)，源码推送不自动发布版本。
