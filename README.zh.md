# MengLuo DSH Desktop

[English](README.md) | 中文 | [更新日志](CHANGELOG.md)

适用于 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 的非官方 Windows 桌面客户端，由个人维护。项目与 DeepSeek 无隶属、赞助或背书关系。智能体和 Web UI 由 Harness 提供，本项目负责安装、原生窗口、进程监管与桌面功能。

最新公开安装包见 [GitHub Releases](https://github.com/Coyami-Mengluo/mengluo-dsh-desktop/releases/latest)，改动与公开版本历史见[更新日志](CHANGELOG.md)。源码中的改动可能尚未包含在最新安装包中。

## 安装与使用

从 [GitHub Releases](https://github.com/Coyami-Mengluo/mengluo-dsh-desktop/releases/latest) 下载 **setup.exe 安装版**。首次启动会让你选择官方 Harness 版本和下载源：默认的官方 npm，或第三方 npmmirror 镜像。版本信息始终来自官方 npm；已有且通过验证的版本会直接沿用。安装包包含 Electron、安装用 Node 和 npm，不预装 Harness。支持 Windows x64；未签名的预览版可能触发 SmartScreen 警告。

关闭主窗口会隐藏到托盘。右键托盘，或按 **Ctrl+Alt+U** 打开菜单；选择“退出”才会停止客户端和 Harness。菜单也提供 Harness 终端，使用已选运行时的 Node 和 `dsh`，以及固定版本的 npm/npx/pnpm 工具。Git 只有在 Windows 已安装时才可用。

精简后的菜单保留“打开 Harness 终端”“客户端设置”和“退出”；托盘另有“显示主窗口”。存在可查看的更新进度时，菜单会显示“查看更新进度”。关闭独立设置窗口只会隐藏它，不会停止 Harness。

透明应用图标是维护者提供的 AI 生成插画，不是 DeepSeek 官方标志。来源与独立使用说明见[图标素材说明](assets/ARTWORK.md)。原先采用 MIT 的几何 SVG 仍保留作为替代素材。

## 客户端设置与下载源

首次安装页和客户端设置提供“跟随系统 / 简体中文 / English”。切换即时应用到客户端窗口、菜单和更新进度，偏好保存在客户端自己的 `language-settings.json`，不会重启 Harness，也不翻译官方界面或改写社区插件名称与介绍。“跟随系统”在中文系统语言下使用简体中文，其余使用 English。

从托盘或 **Ctrl+Alt+U** 菜单打开“客户端设置”，配置项分为五区：

- **Harness：**当前版本、安装与更新、更新通道、自动检查和检查频率。Harness 自动检查保留原有行为：发现更新后可在后台下载并校验，准备完成再提醒你确认重启切换。
- **插件：**社区插件发现列表和 Harness `web` profile 中用户额外安装的插件；只读检查更新，安装、更新及卸载均须用户确认。
- **下载与网络：**Harness 下载源、连接检测和当前系统代理状态。
- **客户端更新：**桌面客户端版本、手动检查、每日自动检查、下载进度及确认重启安装。
- **关于与日志：**项目链接、版本与许可信息、日志入口。

首次安装页和网络设置共用应用用户资料目录中的 `download-settings.json`。切换下载源仅对后续由客户端管理的 Harness 安装和更新生效，不改变正在进行的任务；不修改系统全局 npm 配置或 Harness 终端的 npm 配置，也不改变 Git 插件下载与客户端 GitHub 更新源。

选择 npmmirror 只改变 npm 软件包文件的下载途径。客户端先从官方 npm 获取精确版本、依赖图和 SHA-512 完整性校验值，再经镜像下载已锁定的软件包。镜像连接失败或缺少文件时，会在原有超时预算内尝试从官方源下载同一版本和依赖。完整性校验失败不会被绕过；失败的候选版本不会启用，也不会偷偷换成旧版本。

npmmirror 是第三方服务，可能存在同步延迟，**不保证一定提速**。选择镜像后仍须能连接官方元数据服务；依赖解析、落盘校验和启动测试也仍需要时间。连接检测还会比对目标版本在镜像与官方 npm 的元数据及完整性摘要：首次安装按下拉框所选版本，设置页按待切换/可更新/当前版本。条目一致不保证全部依赖和包文件已经同步，也不代表实际下载速度。这些设置不会修改官方 Harness 界面。

## 插件

安装、更新或卸载完成后，可点击 **重启 Harness** 加载变更，无需退出客户端窗口。确认前请先保存工作，正在执行的任务会中断；不会安装已下载的客户端更新。

冷却提示会区分客户端保护、GitHub 搜索额度、插件信息额度和服务端临时限流。检查插件更新的额度不会锁住目录刷新；仅当对应请求额度耗尽时才使用 GitHub 的额度重置时间，临时限流按 `Retry-After` 或退避等待，不会误套用无关的小时级重置时间。

打开插件页时先读取缓存，再决定是否发送请求。当前客户端进程内，搜索页缓存 5 分钟，普通浏览的插件信息缓存 15 分钟，精确 Git 提交下的文件最长缓存 24 小时。相同的进行中 GET 请求合并发送，取消一个调用不会中断其他使用者。缓存按最近使用情况淘汰，最多保留 256 项、8 MiB 序列化 JSON，退出客户端后清空。手动刷新或检查仍重新查询可变信息；安装和更新前如最新分支或 npm 版本查询失败，不会用旧缓存冒充成功。重复检查同一个 GitHub 更新时会复用不可变文件，不再重复获取。

“客户端设置 → 插件”包含商店、已安装列表和本地快照。商店搜索带有 GitHub [`dsh-plugin` topic](https://github.com/topics/dsh-plugin) 的公开、未归档、非 fork 仓库，按最近更新时间排序。关键词会提交给 GitHub，在仓库名称、描述和 README 中远程搜索，不再只筛选已经加载的列表。每页最多 100 条，点击“加载更多”继续查看后续页。GitHub 每次搜索最多开放 1,000 条结果，也可能返回不完整结果；看到提示时请缩小关键词范围。未添加该 topic 的仓库不在商店搜索范围内。

搜索仅在点击“搜索”按钮或按 Enter 时提交；打字、停顿、清空输入框和输入法选字结束均不会发送请求。近期查询的分页结果会缓存，以减少匿名 API 请求。提交新关键词时会取消或忽略旧请求，避免较晚返回的旧结果覆盖新搜索。拥有 topic、被列入商店或声明了插件包，均不代表安全或兼容认证。安装前请查看作者、源码、权限、依赖和许可证；第三方插件可以执行代码。不能确认仓库根目录为可安装 Harness 插件包的项目，请依照作者说明手动安装。

搜索、翻页和刷新在主进程共用请求额度：每滚动 60 秒最多发送 8 次搜索请求，两次发送至少间隔 1 秒；已经发送后再取消的请求仍计数。手动刷新目录和检查插件更新各有 30 秒冷却。普通 GitHub 插件元数据另有每小时 50 次的本地额度，不占搜索额度。GitHub 返回限流或额度耗尽时，客户端按响应中的恢复时间暂停请求；未提供有效时间的限流使用至少 60 秒的退避。界面显示倒计时，结束后由用户重试，不会自动循环请求。近期查询缓存和上一批结果仍可查看，旧结果会标明原关键词。以上保护按当前客户端进程计数；共享代理出口的其他程序仍可能用掉服务端额度，因此不能保证永不限流。

进入插件页或点击检查更新，只会读取公开元数据；**不会在后台自动更新插件**。安装、更新或卸载需要明确点击按钮并确认，再调用当前运行时配套的官方 Harness 插件命令。npm 更新固定到精确版本，商店安装和 GitHub 更新固定到精确提交。官方自带组件不在这些按钮的管理范围内。壳会阻止插件修改与自身的 Harness 更新任务并发；请勿同时在外部终端或官方 UI 修改同一个 profile。

已安装列表管理 `web` profile 中用户额外添加的插件。通过商店首次安装 GitHub 插件时，会记录选定分支和精确提交，供后续检查使用。已有 GitHub 插件若缺少可信的已安装提交或跟踪分支，以及本地包、其他未支持来源，会显示更新状态未知，不猜测升级目标。未提供兼容声明时显示未知；作者声明的版本范围也不等于通过了实际兼容测试。

插件任务使用系统代理，显示当前阶段、活动和有限长度的近期输出，超时上限为 30 分钟。官方命令没有提供可靠总量时，不虚构下载百分比。Harness 的镜像源选项仅负责受管理的 Harness 运行时下载，不修改插件的 registry、系统全局 npm 配置或 GitHub 来源。

壳仅在自己的用户资料目录保存最小来源记录 `plugin-sources.json`（包名/spec、仓库、跟踪分支与提交），不把这些记录写入官方插件配置，也不保存凭据。浏览商店或检查更新会通过系统代理，将搜索关键词及相应的公开仓库名或 npm 包名发送给 GitHub API 或官方 npm，不携带账号凭据，也不上传聊天或插件配置。请勿在商店搜索框中输入密钥等私密信息。详见[插件安全边界](SECURITY.md#plugin-boundary)。

### 本地插件快照与回滚

用户确认安装、更新或卸载插件后，客户端会先复制并校验整个 Harness `web` profile，以及自己的 `plugin-sources.json`。快照包含该 profile 的依赖清单、锁文件、配置和实际已安装软件包文件；快照创建失败时，不会开始执行插件命令。快照保存在本机客户端资料目录，不上传，也不进入源码导出。

在“插件 → 本地快照”中选择快照并确认回滚，会恢复**整个已保存的 `web` 环境**，也包括该 profile 中的其他插件。客户端会暂时停止 Harness，请先结束正在执行的任务。恢复使用本地文件，离线完成，不下载软件包或执行安装脚本；成功后重新启动 Harness。恢复要求 Harness 版本相同、快照校验通过，且当前 profile 和来源记录仍与对应操作结束时记录的状态一致。后续修改可能让较早的快照无法恢复，客户端不会静默覆盖这些变化。

快照不恢复 Harness 运行时、聊天、工作区、其他 profile，或插件写到该 profile 之外的文件。支持内部软件包目录链接，拒绝外部链接和不安全路径。正常保留目标为最近五个已结束操作的快照；未完成、无法校验的副本，以及单独保留的回滚恢复副本可能继续留存，因此磁盘占用不以五份快照为上限。回滚中断时会暂停后续插件修改和 Harness 启动，须从本地快照入口校验并修复保留的恢复事务。

**profile 配置可能包含密钥；这些本地备份未加密。** 请按真实用户资料保护它们，不要把快照、恢复副本或配置放入 issue、截图或公开压缩包。详见[快照安全与恢复限制](SECURITY.md#local-plugin-snapshots)。

## 两条独立的更新路径

- **客户端更新：**每天自动检查本仓库 GitHub Releases 的稳定版，也可从“客户端设置 → 客户端更新”手动检查。下载和重启均须用户确认。安装版优先差分下载；缺少缓存、旧版 blockmap 或服务器不支持 HTTP Range 时，会回退完整安装包。进度窗口根据实际数据显示传输量、速度、百分比和可用的预计时间。平时退出客户端不会自动安装已下载的更新。便携版和开发版只提供发布页入口，不自动替换自身。
- **Harness 更新：**按所选文件下载源安装一个精确的官方 npm 版本及其完整生产依赖，在隔离运行时目录内完成校验和启动测试，确认重启后再切换。自动检查可在后台准备候选版本。这条路径不使用客户端的 GitHub 更新，也不是增量更新；npm 准备、镜像下载和官方源重试共用原有的 30 分钟超时预算。

客户端安装器替换应用文件，不删除当前用户的 Harness 运行时目录、插件或会话。确认重启客户端会停止当前 Harness 任务，请先完成工作。没有新 profile 时会沿用旧私有客户端的 profile 与 workspace。官方 Harness 可能修改自身的数据格式，本项目不能保证兼容所有未来版本，也不能迁移未公开的数据格式。

## Harness 版本管理

在“客户端设置 → Harness → 版本管理”选择已安装版本，或获取官方历史版本（刷新间隔 30 秒）。下载使用当前选择的下载源，安装到独立槽位，不会立即登记为待切换版本。已安装版本可离线切换：文件校验与临时数据隔离启动测试通过后，才停止后台并重启客户端。每个版本使用自己的 Node 和官方配套依赖，不接受任意路径或软件包 URL。

手动切换后自动锁定所选版本。锁定期间仍可检查和提醒新版，但不自动下载或登记切换；开启锁定也会取消已有的待切换更新。解除锁定后恢复常规更新策略。

**降级前**请结束任务，关闭其他 Harness 实例和外部终端。客户端停止自己的后台后，完整复制并校验 Harness 数据目录及客户端插件来源记录，再登记切换。备份未加密，可能含密钥和聊天，保存在客户端用户资料目录的 `harness-data-backups` 中，可从设置打开。只有包含 `manifest.json` 的目录才是完成并验证的备份。上限为 2 GiB / 100000 项；不安全路径、数据目录外的链接、文件变化或备份失败都会阻止降级。备份不自动清理、不上传；Harness 数据目录外的工作区文件不包含在内。

旧版本可能不兼容新数据和插件。启动失败可回退可用的已安装运行环境，但**不会自动还原备份中的数据**。整份数据恢复需要手动操作：先退出所有 Harness 进程，另外保留当前数据，再核对备份清单后恢复。本功能不保证所有官方版本均能兼容。

## 从源码构建

使用 **Windows x64 和 Node.js 24.19.0**，无需下载官方 Harness 源码，也不依赖 pnpm workspace。

```powershell
npm.cmd ci --ignore-scripts
npm.cmd run prepare:electron
npm.cmd run prepare:icon
npm.cmd test
npm.cmd start
```

生成安装版与便携版：

```powershell
npm.cmd run dist:win
npm.cmd run check:release
```

构建会校验本机已有的固定版本 Node/npm；没有合适副本时，从 nodejs.org 下载固定的 Node 发行包。下载包摘要、Node 可执行文件摘要和 Authenticode 身份，以及 npm 文件树指纹均会校验。构建下载需要联网。保留 `package-lock.json` 并使用 `npm ci`，不要复制其他工程的 `node_modules`。

`dist/` 包含安装器、配套 `.blockmap`、便携版和 `latest.yml`。本地打包**不会上传任何文件**。首次手动安装、发布顺序、保留旧 blockmap，以及公开发布前仍需验证的事项，见[发布说明](docs/RELEASING.md)。
