# Contributing

Start with the concise [architecture overview](docs/ARCHITECTURE.md) for shell/runtime ownership, the two updater paths, plugin recovery, and trust boundaries.

Portable source tests can also run on Linux/macOS with `npm ci --ignore-scripts`, `npm run prepare:icon` and `npm test`. Windows-specific cases are skipped there; native smoke tests, staging and packaging still require Windows x64. The portable CI only checks source: it never builds or publishes installers. Passing it does not mean the desktop application supports Linux/macOS.

Use Windows x64 and Node.js 24.19.0. Install the locked development dependencies with `npm ci --ignore-scripts`, then run `npm run prepare:electron` and `npm run prepare:icon`. Dependency installation scripts are disabled; the explicitly invoked Electron downloader uses its pinned package checksums.

Run `npm test` for local behavior tests, `npm run smoke:setup` for the isolated native first-install and titlebar scenario, and `npm run smoke:tray` for tray lifecycle checks. These fixtures do not use your existing Harness home or start a real model session. Run `npm run smoke:client-update` and `node --test tests/shell-differential.test.mjs` before changing updater code. The differential test uses a loopback server and non-executable synthetic data; it never launches an installer.

For the full main-process integration checks, first run `npm run stage:node` and then `npm run stage:npm`. A clean checkout does not contain the built-in Node/npm resources required by the real startup entry point. Then run `npm run smoke:main`, `node scripts/smoke-main.mjs --snapshot-recovery`, and `node scripts/smoke-main.mjs --plugin-restart`; these use isolated application data. The restart case launches a synthetic loopback service under the staged Node and verifies stop/start, renderer readiness, same-version selection and window retention, without running official Harness or plugins. Staging verifies the pinned toolchain and may download it, but does not package or publish a release. CI performs these prerequisites explicitly.

For settings changes, run `node scripts/smoke-settings.mjs` (and `--packaged` after packaging). It uses an isolated profile and mock state to exercise the five settings sections, narrow-window light/dark layout, fixed IPC actions, focus/scroll preservation, and hide/reopen behavior without real downloads or installation. Keep the tray and **Ctrl+Alt+U** menu short; preference controls belong in **Client settings**, not in the official Harness renderer.

The first-install source selector and network settings must share the per-profile `download-settings.json`. Keep source identifiers allowlisted, block changes during a managed installation, and do not write global or terminal npm configuration. Mirror transport must preserve the official exact version, dependency graph and SHA-512 integrity. Add regression coverage for missing mirror files, transport failures, official fallback under the shared timeout, integrity failures and graph mutation; a retry must never disable verification. Connection checks are not a throughput benchmark or proof that every version has synchronized. Do not claim compatibility with untested historical or future Harness versions.

Do not change the official renderer, weaken runtime verification, remove third-party license notices, or bypass confirmation before switching the active Harness version or installing a client update. Add tests for cancellation, failure, sender validation and late callbacks when changing update/lifecycle code. Keep README.md and README.zh.md aligned. Use `npm run check:release` before preparing a source archive.

Preserve the distinction between automatic update paths: client checks only notify until download is confirmed, while Harness checks may prepare and startup-test an isolated candidate in the background. Switching the active Harness version and installing a downloaded client update still require restart confirmation. A Harness mirror preference must not redirect the GitHub client-update feed or the pinned toolchain downloads.

Forks must change `src/release-config.mjs` and repository metadata together before distributing their own builds. Do not redirect users to a release repository they did not choose or ship a GitHub token. Local packaging does not publish; publishing requires a separate maintainer action.
